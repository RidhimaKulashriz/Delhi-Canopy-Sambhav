# DelhiCanopy Round 2 — 75-Second Judge Demo

## Demo Goal

The demonstration shows that DelhiCanopy does not let a climate recommendation become field-ready merely because it looks plausible. TrustOps adds a repeatable quality gate that holds a decision until its mandatory evidence, credibility signals, red-team risks, and accountable human review are all complete.

| Time | Presenter action | What the judge should see |
|---|---|---|
| 0–10 seconds | Open **TrustOps Gate** from the existing navigation and select the Shahdara planting strategy. | A live climate decision starts at **0/100** and is visibly **QUALITY HELD**. |
| 10–20 seconds | Point to the four evidence cards and the two red-team challenges. | The release control is disabled because records are missing, risks are unresolved, and no reviewer is named. |
| 20–35 seconds | Click **LOAD WINNING DEMO**. | The deterministic demonstration packet fills all four evidence records, demonstrates explainable credibility scores, resolves both challenges, and assigns a reviewer. |
| 35–47 seconds | Read the three quality conditions in the Decision Release card. | The readiness score reaches **100/100** only after all four evidence checks, two challenges, and the reviewer condition pass. |
| 47–58 seconds | Click **APPROVE FIELD REVIEW**, then **COPY AUDIT RECEIPT**. | The status changes to **REVIEW READY** and a compact, reproducible receipt is generated with readiness, evidence, challenge, reviewer, status, and timestamp. |
| 58–68 seconds | Click **RESET GATE**. | The same decision returns to **QUALITY HELD** with empty evidence and blocked challenges, proving this is a repeatable check rather than a decorative completion state. |
| 68–75 seconds | Open the linked Planting Space Finder or AI Planner path. | TrustOps is shown as an additive control layer around the existing decision workflows, not a replacement for them. |

## Suggested Spoken Narrative

> “DelhiCanopy already finds planting opportunities and produces climate recommendations. For Round 2, TrustOps prevents a recommendation from being treated as final until it survives the same repeatable quality process every time. We start with the decision held at zero. The gate requires traceable evidence, credibility signals, an attempt to challenge the decision, and a named human reviewer. The demo packet is deterministic, so judges can replay the entire pass state in seconds. Only then can we release it for field review and produce an audit receipt. Resetting immediately returns the decision to a held state. This is quality control and traceability, not a permit or a substitute for site verification.”

## Safety Boundary

TrustOps evaluates the completeness and traceability of decision documentation. It does not grant legal permission, replace an on-site assessment, guarantee a predicted climate outcome, or authorize physical planting.
